# 多项目资源调度器（GUI版）——项目规格说明

## 1. 项目概述

### 1.1 项目名称

多项目资源调度器（Multi-Project Resource Scheduler，简称 MPRS）

### 1.2 项目目标

开发一款**桌面图形界面应用**，用于咨询公司或项目型组织的多项目人力资源调度与管理。系统能够根据员工技能、工时容量、项目优先级和截止日期，自动生成合理的资源分配方案，并支持手动调整、冲突检测和“What-if”情景模拟。

### 1.3 核心价值

- **自动化调度**：根据业务规则自动分配资源，减少人工排期耗时
- **冲突预警**：实时检测并提示资源超载、技能缺失等冲突
- **决策支持**：通过模拟模式，辅助管理者评估“新增员工”或“调整优先级”等决策的影响
- **数据持久化**：所有配置和分配数据跨会话保留


## 2. 用户角色

| 角色 | 职责 | 使用频率 |
|------|------|----------|
| **项目管理者** | 创建/管理项目、设定优先级、审核分配方案 | 高频 |
| **资源经理** | 管理员工信息、监控资源利用率、处理冲突 | 中频 |
| **执行人员（查看者）** | 查看个人分配情况（只读） | 低频 |


## 3. 功能需求

### 3.1 员工管理（资源池）

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 添加员工 | 录入姓名、技能集（多选）、每周工时容量（默认40h） | 必须 |
| 编辑员工 | 修改技能集或容量 | 必须 |
| 删除员工 | 从系统中移除（需确认，且仅当无进行中分配时允许） | 必须 |
| 查看员工 | 显示员工信息及当前所有项目分配明细 | 必须 |
| 负载可视化 | 以柱状图展示每位员工当周的负载率（%） | 必须 |

### 3.2 项目管理

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 创建项目 | 录入项目名称、所需技能及工时需求、优先级（1-5）、截止日期 | 必须 |
| 编辑项目 | 修改优先级、截止日期或技能需求 | 必须 |
| 删除项目 | 删除项目（需确认，相关分配自动释放） | 必须 |
| 查看项目 | 显示项目详情、当前分配方案、进度（%） | 必须 |
| 筛选排序 | 按状态（规划中/已分配/进行中/已完成/延期）或优先级筛选 | 建议 |
| 进度更新 | 手动更新项目完成百分比 | 必须 |

### 3.3 自动调度与分配

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 自动生成分配方案 | 系统根据规则自动为选中项目生成资源分配 | 必须 |
| 手动调整分配 | 用户通过滑块或数字输入调整某员工在某项目上的工时 | 必须 |
| 实时合规校验 | 手动调整时，界面实时提示是否违反约束（变红/警告） | 必须 |
| 分配确认 | 用户审核后确认分配，项目状态变更，数据持久化 | 必须 |
| 分配回滚 | 回退到上一个已确认的分配版本 | 必须 |

### 3.4 冲突检测与修复

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 全局冲突检测 | 检测所有项目中存在的资源冲突（超载、技能缺失等） | 必须 |
| 冲突列表展示 | 弹窗列出所有冲突，分类显示（错误/警告） | 必须 |
| 自动修复 | 对每条冲突提供“自动修复”按钮，系统重新计算 | 必须 |
| 手动处理 | 用户可手动调整后重新检测 | 建议 |

### 3.5 What-if 模拟

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 进入模拟模式 | 界面切换至模拟状态（视觉标识），所有操作不影响持久化数据 | 必须 |
| 添加虚拟员工 | 在模拟模式下添加临时员工（带标识，不会持久化） | 必须 |
| 实时重算 | 添加虚拟员工后，系统立即重新计算所有项目分配，界面更新 | 必须 |
| 模拟报告 | 生成模拟前后的对比报告（文本格式） | 建议 |
| 应用模拟结果 | 将虚拟员工转为真实员工并持久化，或放弃模拟恢复原始数据 | 必须 |

### 3.6 报告与数据导出

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 利用率报告 | 按周生成所有员工的利用率统计 | 必须 |
| 项目进展报告 | 显示所有项目的状态、进度、分配详情 | 必须 |
| 数据导出 | 将当前所有数据导出为JSON文件 | 必须 |
| 数据导入 | 从JSON文件恢复数据 | 必须 |


## 4. 界面规格

### 4.2 关键交互流程

**流程一：自动分配**
1. 用户点击中间面板的某个项目卡片 → 该卡片高亮，右侧面板显示当前分配
2. 用户点击工具栏“自动分配”按钮
3. 系统执行调度算法，右侧面板**实时更新**显示建议分配方案
4. 用户可拖拽工时滑块微调（实时合规校验）
5. 点击“确认” → 方案生效，数据持久化，项目状态更新

**流程二：冲突诊断与修复**
1. 用户点击“冲突检测”按钮
2. 弹出**冲突列表对话框**，分类展示所有冲突（红色=错误，黄色=警告）
3. 每条冲突旁有“自动修复”按钮
4. 点击修复 → 系统重算，对话框和主界面同时更新
5. 全部修复后对话框自动关闭，主界面状态栏显示“无冲突”

**流程三：What-if 模拟**
1. 用户点击“模拟模式” → 界面背景变为浅黄色，状态栏显示“模拟中 🔬”
2. 左侧面板出现“+ 虚拟员工”按钮，点击后添加带 🧪 标识的员工
3. 系统立即重算，右侧分配方案更新，展示“模拟结果”
4. 用户可继续添加多个虚拟员工，观察变化
5. 点击“退出模拟” → 恢复到原始数据；或“应用模拟” → 虚拟员工转为真实员工

### 4.3 数据可视化

**图表一：员工利用率柱状图**
- 位置：左侧面板底部或独立弹窗
- 展示维度：当前选中周，所有员工的负载率（0%-100%）
- 视觉规则：≤80% 为绿色，80%-95% 为黄色，>95% 为红色

**图表二：项目甘特图**
- 位置：中间面板或独立弹窗
- 展示维度：时间轴（周），各项目的持续时间和当前进度
- 视觉规则：已完成部分为深色，未完成部分为浅色


## 5. 业务规则（共8条）

系统必须实现并强制执行以下约束：

| 编号 | 规则名称 | 规则描述 |
|------|----------|----------|
| **R1** | 技能匹配 | 分配给某项目的员工必须拥有该项目所需的所有技能之一（即至少匹配一项） |
| **R2** | 工时容量上限 | 任何员工在任意一周的总分配工时 ≤ 该员工的`weekly_capacity` |
| **R3** | 优先级抢占 | 高优先级项目（数值小）可占用低优先级项目已分配的工时；被抢占的低优先级项目进入“待重新分配”队列 |
| **R4** | 连续工作约束 | 同一员工分配到同一项目的连续周期不得少于2周（避免频繁切换） |
| **R5** | 最小团队规模 | 任何项目至少分配2名不同技能领域的员工 |
| **R6** | 截止日期反推 | 根据截止日期自动计算每周最低需投入工时，若不可行则产生“无法按期完成”警告 |
| **R7** | 负载均衡偏好 | 在满足所有硬约束的前提下，优先使所有员工的负载率差异不超过20% |
| **R8** | 分配锁定期 | 已执行超过1周的分配方案不可直接修改；变更需通过“变更请求”流程（即生成新版本方案） |

**规则优先级说明**：
- 硬约束（违反即错误）：R1, R2, R5, R8
- 软约束（尽量满足，违反为警告）：R3, R4, R6, R7


## 6. 数据模型

### 6.1 员工（Employee）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 唯一标识，自动生成 |
| `name` | string | 是 | 员工姓名 |
| `skills` | list[string] | 是 | 技能列表，如 `["python","react"]` |
| `weekly_capacity` | int | 是 | 每周可用工时，默认40，范围20-60 |
| `is_virtual` | boolean | 否 | 是否为虚拟员工（模拟模式），默认false |

### 6.2 项目（Project）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 唯一标识，自动生成 |
| `name` | string | 是 | 项目名称 |
| `priority` | int | 是 | 1（最高）至5（最低） |
| `status` | enum | 是 | `planning` / `allocated` / `active` / `completed` / `delayed` |
| `required_skills` | dict | 是 | `{"skill": hours_required}`，如`{"python":40,"react":30}` |
| `total_effort_hours` | int | 是 | 总预估工时 |
| `deadline` | date | 是 | 截止日期，格式 ISO 8601 |
| `start_date` | date | 是 | 计划开始日期 |
| `progress` | int | 否 | 完成百分比，0-100，默认0 |
| `allocations` | list | 否 | 当前分配详情列表 |

### 6.3 分配明细（AllocationItem）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `employee_id` | string | 是 | 员工ID |
| `skill` | string | 是 | 该员工在该项目中承担的技能 |
| `hours` | int | 是 | 每周分配工时 |
| `week_start` | date | 是 | 分配起始周（周一日期） |
| `week_end` | date | 是 | 分配结束周（周日日期） |

### 6.4 分配方案版本（AllocationPlan）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 唯一标识 |
| `project_id` | string | 是 | 关联项目 |
| `version` | int | 是 | 版本号，从1递增 |
| `status` | enum | 是 | `draft` / `approved` / `executing` / `rolled_back` |
| `created_at` | datetime | 是 | 创建时间 |
| `assignments` | list | 是 | 该版本的分配明细列表 |
| `change_reason` | string | 否 | 版本变更原因 |


## 7. 技术约束

| 类别 | 约束 |
|------|------|
| **编程语言** | Python 3.9+ |
| **GUI框架** | `tkinter`（Python标准库） |
| **数据存储** | JSON文件（`json`标准库读写） |
| **第三方依赖** | **零依赖**，仅使用Python标准库 |
| **数据文件位置** | `~/.mprs/data.json`（默认，可配置） |

### 7.1 数据存储规范

- 所有数据以UTF-8编码存储在单个JSON文件中
- 每次修改后自动保存（非手动触发）
- 启动时若数据文件不存在，自动创建初始空数据
- 数据文件损坏时，显示友好错误提示并提供“从备份恢复”选项（如有）

## 11. 附录

### A. 术语表

| 术语 | 定义 |
|------|------|
| 负载率 | 员工实际分配工时 ÷ 容量 × 100% |
| 虚拟员工 | 仅在模拟模式下存在的临时员工实体，不持久化 |
| 分配方案 | 一个项目的一组完整分配明细，带有版本号 |
| 锁定期 | 分配方案确认执行后，一周内不可直接修改的保护期 |
